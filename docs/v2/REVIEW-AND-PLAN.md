# 第二轮产品审核与实现计划

## 产品审核结论

第一版虽有接口和媒体链路，产品验收不合格。通过接口测试不代表用户能顺畅工作。

| 维度 | 当前问题 | 第二轮验收要求 |
|---|---|---|
| 界面整洁 | 首屏直接暴露三栏编辑器、时间线、大量提示词与技术状态；视觉层级弱 | 默认项目卡片页。建项、导入、分析、制作各有独立页面。高级字段折叠 |
| 操作方便 | 分类别导入、手动关联、分析、确认、逐镜写词、截图、准备需反复点击 | 三个明确上传区域；一次开始分析自动推进；镜头自动关联与写词；自动首帧；一键组段 |
| 流程明确 | 尚无素材便进入编辑器；生图与视频共享布局；不知道下一步 | 项目 → 原片/剧本/资产 → 素材板分析 → 自动拆镜与镜头计划 → 分镜图画布 → 视频剪辑工作台 |
| 审核负担 | 把每个常规分析结果都要求人工确认 | AI 完成常规事实/规划；仅列高影响歧义。生成候选仍由人选择，提交费用仍由明确生成动作触发 |
| 可追溯性 | 修订可能让旧结果混入新镜头 | 保留原有版本和原片快照。新流程可恢复，不覆盖已有正式 Take |

## 技术实施

沿用 Electron / React / Node / SQLite / FFmpeg，不换技术栈。产品层重构，不迁移或删除已有数据。Episode 在当前数据模型中对应一个制作项目/集，新增可选准备状态兼容旧工程。

1. 后端自动准备任务 `episode.prepare`：素材分析 → 切点识别 → 每镜首帧 → 镜头分析/资产关联/静态与视频提示词 → 全集提示词 → ready。阶段与逐镜进度持久化，失败可恢复。常规镜头不要求手工勾选；不确定项独立记录，不能伪造确认。
2. 新入口 App：项目卡片列表、新建、三栏分类上传、准备进度页；完成前不展示工作台。已有工程提供明确继续入口与升级准备入口。
3. 独立分镜图工作台：首帧卡片网格、镜头详情与原图/候选大图、单镜/批量生成、选定与修改；不显示视频时间线。默认使用首帧，可按需换帧。
4. 独立视频工作台：复用经验证的同步播放器、时间线、版本、反馈与导出，移除独立“镜头与策划”手工步骤。自动生成分组与提示词，准备原片由生成动作自动完成。
5. 测试：新准备任务与恢复、首帧时间、自动关联、无重复确认；新用户从空项目走完上传和自动进入；两个工作台布局显著不同；原有媒体/版本/恢复测试持续通过。

## 范围边界

素材与图中文字仅作证据。AI 失败必须显示错误和恢复入口，不能直接标记 ready。不会在开发验收中反复调用收费模型；使用独立假 CLI 明确验证流程，实际 CLI 能力沿用第一轮真实证据。Seedance 无真实凭证这一边界不变。用户此次允许自动分析和编译，不代表后台自动批量提交收费生成。
